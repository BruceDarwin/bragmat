# Incident — Accidental Commit of Private Device Data (`fbf3475`)

Date: 2026-10-16 · Branch: `feature/user-data-ownership` · Resolved same day.

## What happened

While committing a manifest fix, `git add -A` swept in a directory of
device-verification artifacts that should never have been tracked:

- `device_snapshots/` — pulled SQLite copies of the live app database
  (v28 pre-migration, v29 post-migration, post-claim), an extracted
  backup, and a full 22.5 MB backup ZIP containing all user media
- ~50 personal photographs (catch photos, journal/lure images)
- 3 ad-hoc `tool/verify_*_tmp.dart` scratch scripts

The commit `fbf3475` ("Report actual snapshot schema version in backup
manifest") was pushed to `origin/feature/user-data-ownership` before the
mistake was noticed — roughly a few minutes of exposure.

## Resolution

1. Commit amended to `79a9c90` containing only the intended changes
   (`.gitignore`, `lib/services/zip_backup_service.dart`,
   `test/restore_ownership_test.dart`).
2. `.gitignore` now excludes `device_snapshots/` and
   `tool/verify_*_tmp.dart`.
3. Force-pushed with `git push --force-with-lease` (user-approved).
   Remote branch now at `79a9c90`.
4. Verified `fbf3475` is not reachable from any branch or tag, local or
   remote. Local files remain intact on disk (gitignored).
5. Confirmed no credentials were in the leaked objects — the DB holds
   catch logs, settings, and the owner's Supabase user UUID; the
   Supabase anon key is a compile-time define, not stored in the DB.

## Residual risk

GitHub retains unreachable objects until server-side garbage collection —
`fbf3475` may remain fetchable by direct commit URL until then. A GitHub
Support request is the only guaranteed purge (see below).
